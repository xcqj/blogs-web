## 0. 核心前提（必读）

**Stitch 生成的页面与本站的数据接口、功能，并不一一对应。**

它按 prompt 想象一个"看起来合理"的页面，并不知道本站有哪些字段、哪些功能已实现、哪些被明确排除。所以每张图默认会混入三类不存在的东西：

1. **没有数据对应的展示**：刊期/卷号、ISSN、DOI、阅读时长、更新频率、点赞收藏数、评论区、编委会
2. **没有实现的功能入口**：版本恢复、版本差异对比、自动保存、订阅、导出 PDF、AI 写作、定时发布
3. **装饰性伪技术文案**：`UTF-8 STRICT`、`REPOSITORY ENCRYPTED`、`DEP. 01 // MS. REF`、`DRAFT SYNCED // 1,420 WORDS`

**结论：看图只取四样东西——版式结构、信息层级、配色与字体、图文关系。** 数据字段与功能一律以 `docs/blog-api.md`、`app/types/**` 和现有组件为准。图上多出来的一律按"编的"处理，不当成需求；除非用户在文档里明确要求新增。

### 4.2 响应式降级规则（Stitch 只出桌面稿，移动端由此推导）

断点沿用 UnoCSS 默认（sm640 / md768 / lg1024 / xl1280，D28 口径，**不自造断点**）：

| 断点 | 布局 |
|---|---|
| ≥1280 | 容器 1100 居中；主列 + 右栏咬合（66/34），右栏 sticky |
| 1024–1279 | 容器 100%（左右 24px）；右栏保留在右侧，收窄至 300px；头条图 220×124 |
| 768–1023 | **右栏下移到主列表之后**（两张卡横排 2 列）；头条改「**图在上、文字在下**」（图满宽 16:9）；列表缩略图 112×63 |
| 640–767 | 单栏；列表缩略图 96×54；导航收汉堡 |
| <640 | **列表行缩略图隐藏**（只保留 标题/摘要/meta 三层）；头条图满宽 16:9 保留（首屏视觉锚点）；hero 隐藏右侧状态卡、标题降到 32px；触控目标 ≥44px |

三条原则：

1. 图片按比例缩放不裁主体：`aspect-ratio` + `object-fit: cover`
2. 断点切换**只改列数与尺寸档，不改信息层级**——三层信息在任何断点都必须保留
3. 主题与断点正交，不做"深色移动版"这类组合特例（一套 DOM + 变量，天然正交）

| 顶栏导航 | 改造 `AppHeader.vue` | 导航仅 首页/标签/搜索；激活项 2px 下边框 |
| 发文页双顶部 | `AppHeader`（全站，64px）+ 页面内操作条（56px，sticky 吸附其下） | 共 120px 不可免；**不要合并成一条**（导航+保存+发布+主题+头像挤不下 1024） |

### 5.1 详情页版式依据（不抽卡，取自「新建文章」屏的正文区）

文章详情页不再单独出屏——发文页编辑器正文区已经把正文排版语言给全了，直接复用：

| 元素 | 依据（编辑器正文区实测结构） |
|---|---|
| 正文 | 17px / 行高 1.75 / 66ch 测量宽；段落间距约 24px |
| 代码块 | 外框 1px 线 + 3px 圆角；顶部栏（左侧色点 + `文件名 // 说明`，右侧语言标签）；代码区等宽 13px / 1.65，可横向滚动，浅底 |
| 行内代码 | 浅底 + 1px 边 + 3px 圆角 + 等宽 13px |
| 引用块 | 左侧 2px 靛蓝实线 + 左侧 padding 16px + 16px 正文 + 次级色；署名行等宽 11px 大写 |
| 标题层级 | 衬线；H1 用页面主标题的 40–48px 档，H2 约 28px，均负字距 |
| 光标/占位 | 详情页不需要（只在编辑器出现） |

## 6. 不吸收清单（落地时逐条核）

- 内联 `style`、px 魔法值、硬编码色值 —— **注意：数值要照抄，写法要重写**。判据是「值对齐、写法重写」：
  Stitch 写 `text-[44px]` → 我们写 `--text-3xl: 48px` 并核对是否 44 还是 48（以 §4.1 为准）；
  Stitch 写 `px-6` → 我们写 `--space-6`。**不许因为"不能搬内联样式"就改成凭感觉重写**——
  2026-10-27 之前的偏差（容器 1100 vs 1180、区块头做成衬线标题、全站边框没渲染）都是这条被误读造成的。
- **编造数据**：ISSN、DOI、同行评议、编委会、审稿人、影响因子、接受率、PDF 下载、订阅、评论区、阅读时长、更新频率、"EST. 20XX"、假人名头衔
- **编造功能（发文页已出现，必须剔除）**：
  - 版本历史里的「恢复」按钮、「差异对比」——**版本恢复是 MVP 明确不做的功能**（PRD/ROADMAP 排除项）
  - 「已自动保存至本地」——本站**不做自动保存**（`ArticleForm.vue` 明确注释：避免误写库）；只能显示「有未保存更改 / 已保存 · HH:mm」
  - 「预计发布刊期（第 N 卷）」「学术许可协议 CC BY-NC-ND」——无字段
- **装饰性伪技术文案**：`MONOGRAPH MANUSCRIPT // CHN-ED`、`UTF-8 STRICT`、`REPOSITORY ENCRYPTED`、`DEP. 01 // MS. REF`、`DRAFT SYNCED // 1,420 WORDS`
- **分类 / 专栏 / 话题 / 归档导航**：Category 永久舍弃（`AGENTS.md` §5 红线）
- 灰色占位块、「破图」图标、无封面时的固定宽高比留空
- 12px 以上大圆角、胶囊按钮（chip/头像除外）、阴影、渐变、发光、玻璃拟态
- 第二种彩色、暖色/黄色（旧 CTA 黄作废）、emoji 图标、彩色插画
- 满屏 hero、大数字指标卡、三列等宽功能卡、logo 墙

## 7. 降级规则（必须有，否则上线即翻车）

| 场景 | 规则 |
|---|---|
| 文章无 `coverUrl` | 缩略图区整体不渲染，标题左移填补；**不留白、不出灰块** |
| 文章无 `summary` | 摘要行不渲染，不预留行高 |
| 文章无 `tags` | meta 行不留多余分隔点 |
| 当前页文章 < 5 篇 | 头条仍取第 1 篇，"共 N 篇"照常 |
| 当前页文章 < 2 篇 | 取消头条形态，全部退普通数据行 |
| 第 2 页起（`/page/{n}`） | 取消 `LATEST` 头条 |
| 标签为空 | 标签卡显示"暂无"，不隐藏整卡 |
| 深色主题 | 图片 `brightness(0.95) saturate(0.92)`，避免照片比页面更亮 |

## 8. 生成纪律（避免重复踩坑）

1. 单屏生成 1–3 分钟；**超时不要重试**，用 `get_screen` 每 30s 轮询最多 10 次。
2. **新屏必须带 `designSystem` 参数**（见 §3 风险 1），否则风格漂移。
3. 局部微调用 `edit_screens`；探索版式用 `generate_variants(aspects: ["LAYOUT"], creativeRange: "REFINE", variantCount: 3)`；`REIMAGINE` 会推翻整个方向，谨慎。
4. 每屏生成后过一遍「数据契约」（§9）与「不吸收清单」（§6），不合格就重生成，不要将就。
5. 定稿后 `download_file` 取截图存 `design/stitch/shots/`，并把 screen id 补进 §2。
6. **不要在 Stitch 里反复调像素**——它只负责"看起来对不对"，精确数值由 `tokens.css` 决定。

## 9. 数据契约（写 prompt 时的允许清单）

```
导航：首页 / 标签 / 搜索（仅三项）
文章字段：标题、摘要、作者名、发布日期 yyyy-mm-dd、阅读量、标签（1~3 个）、封面图（可选）
标签字段：名称、文章数
全站字段：站名 Stack Depth、tagline「把技术一层层读到深处」、文章总数
分页：首页单页最多 10 篇
禁止：见 §6 与 §7
```
